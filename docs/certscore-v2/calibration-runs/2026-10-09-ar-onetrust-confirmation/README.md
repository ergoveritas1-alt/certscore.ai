# Bounded OneTrust confirmation correction (local)

Versioned onetrust_cookie_groups.v2 permits a verified, known, nonempty pre-click group subset, bound to exact cookie identity/value and configuration hashes. It still requires a complete fresh post-click receipt and an exact same-scope instrumented write of that value after dispatch. Complete baselines continue to emit v1; v1 validation/history remain unchanged. No missing groups are inferred, and invalid confirmation evidence does not block an otherwise eligible click or bounded after-click capture. The v2 reader may accept a complete baseline too, subject to its stronger write requirement; the writer intentionally retains v1 for those baselines.

Targeted verification used four fixed sites, one fresh visit per source/site, balanced AB/BA order (two each), and independent consent-proof/Accept/Reject sessions. Source snapshots, bot identity, egress and existing windows match. Both sources completed 4/4 Accept and 4/4 Reject clicks, with 1/4 confirmed per action (Unleashed). Adecco, Sodexo and Receitas Nestle remained unconfirmed. The paired run shows no measured live confirmation gain. This bounded correction passes its fixtures; no further attempt to infer missing live categories is made. The fixed diagnostic sample is not a population or release-acceptance estimate.

The final 38 focused fixture tests, 231 action regressions, 566 contract tests and scan-core/contracts typechecks passed. They cover partial-before/complete-after, partial-after, stale/unbound/wrong-value writes, unchanged values, opposite decisions, configuration drift, duplicate cookies, changed cookie path, unknown baseline IDs, and unchanged v1 validation. Incremental proof storage is estimated below $0.10/month at 100,000 scans; one-time central bookkeeping below $0.10. No additional lane, wait, timeout, retry, screenshot or model call is introduced. No deployment occurred. The following broader sample is tracked separately when complete.
