# CertScore.ai California retained Reject scope

Owner-authorized local implementation and retained replay, October 22, 2026. No Options panels, live scans, deployment or historical production rewrite.

## Problem and versioned correction

The prior California selector accepted necessary-only equivalents and a narrow English Reject/Decline/Deny All label pattern. It left five completed source-bound cookie-consent paths unknown despite their retained canonical Reject classification and exact pre-dispatch control read. Scope is separate from semantic refusal registration, request collection, purpose and response proof.

New `california-post-reject.v4-retained-scope` preserves the old explicit/necessary-only cases and additionally interprets retained v2 direct-label action context. Use the shared canonical classifier, not a new label or vendor list. Require:

- Original source packet hash, scan/authorized-target identity, completed bounded Reject capture and post-click ancestry through the existing retained-presence validation.
- Retained v2 proof identifying a high-confidence direct Reject action with positive `context_satisfied` and `matched_reject` reason codes, plus committed authorized navigation.
- Current canonical action classification of the exact full label as direct Reject with no conditional/payment/subscription variant. The stored match strength must agree. Partial-category wording, opt-out/privacy-preference actions and unsupported variants do not qualify through this expansion.
- A retained control-proof read matching the action selector hash, frame identity, label source and normalized complete label, with one visible/enabled selector result.

The action context originates in the verified cookie-consent action packet. A bare label, selector wording, CMP name, later CMP readback, unrelated baseline lane or policy text cannot independently supply it. This establishes cookie-tracking rejection for the product risk assessment, not a statutory sale/sharing instruction or consent-registration conclusion.

Persist bounded `retained_cookie_reject_scope.v1` metadata on the new typed assessment: original control time, matched term, classifier version, selector/frame hashes and basis. Re-derive it from the retained projection before promoting a concern. Missing, mismatched or modified context remains unknown.

## Scoring and historical semantics

New potential-risk assessments use `california.collection-review.v3-retained-scope` so both full and potential assessment paths share the corrected scope. V1/v2 potential-risk reads retain the previous scope; v1 keeps flat 5 and v2 keeps the 7/11/13/15 scale. Historical full post-Reject v1-v3 reads also retain their scope and qualification behavior, including v3 property-bound corroboration. New effects use CA score `california-regulatory-posture.v17-reject-scope`; old score versions remain supported. Materialization cache v37 separates new local materializations.

No weights, caps, collection qualification, processing restrictions, GPP family or EU presence eligibility change. Full recipient entities are unioned across GPC/Reject/explicit opt-out once; potential-only recipients are separately deduplicated with the existing mixed-family headroom. Full and potential findings continue through typed persistence -> normalized concern -> concern policy -> unified finding/checklist -> canonical score and downstream surfaces. Customer reports retain factual evidence without point explanations.
