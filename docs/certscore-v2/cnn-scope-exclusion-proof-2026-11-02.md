## Identified boundary

A fresh authorized CNN diagnostic ran the existing six local lanes, using local
filesystem/recursive AWS substitutes and the previously approved bounded policy
assistant. A bounded local-only ancestor audit was appended to the existing
geometry RPC and stripped before returning the observation. It established that
the visible Legal Terms and Privacy modal and its policy link had an
`aria-hidden="true"` ancestor. The background document's footer had an `inert`
ancestor. The modal contained Agree, not a visible first-layer Reject control.
This audit is internal diagnosis, not canonical report evidence. No attribute
was changed, no control was clicked and no preference center was opened.

The existing interaction and readable-context gates deliberately reject those
ancestors. Removing their checks, changing CNN's DOM, using a page-wide OneTrust
hint as authorization, opening Options or increasing the Reject window would
contradict the requested safety and budget constraints. The geographic location
of local network egress remains unverified; this does not establish which UI
another region or visitor will receive.

## Implementation

The original live scope check now retains a fixed exclusion code through its
existing RPC. Its public boolean/state behavior and all safety gates remain
unchanged. The Accept geometry resolver retains this code only on its existing
`scope_not_interactive`, zero-actionable diagnostic. The existing privacy-link
read similarly distinguishes an aria-hidden exclusion from generic hidden CSS.
No raw DOM, selector, URL, cookie, identifier or payload is added by the code.

The independently versioned `consent_scope_exclusion.v1` object is optional and
strict. Its reason is one of aria_hidden, inert, hidden, transparent or
unavailable. Packet schemas reject a scope exclusion attached to an actionable
snapshot, an incompatible policy-link outcome, unknown reasons or extra fields.
Legacy packets retain their prior meaning and need no reconstruction.

The materializer explains only validated, same-scan, same-target packet facts.
An earlier exclusion cannot replace a later click-attempt failure. Wording
describes a checked scope, without asserting it was the sole failure cause.
Existing assessment -> normalized concern/policy -> unified checklist -> persisted
report hydration -> shared report/API/export/PDF handling supplies the wording.
This does not create a finding, change a check status, confer credit or change a
score. Renderers do not infer exclusion reasons from labels or screenshots.
The existing passive link and action status remain unknown/incomplete when the
proof gates cannot be met. Missing historical reasons remain unspecified.

This is a diagnostic repair, not proof of successful CNN policy access or
Accept/Reject execution. A successful action must still pass every original
source, target, document, context, uniqueness, label, hit-target and dispatch gate.
Positive hermetic fixtures verify that genuine available controls still execute;
CNN-shaped aria-hidden fixtures verify that Agree remains unclicked.

Public API/OpenAPI/SDK row shapes are unchanged: the shared canonical detail
string carries the explanation. Public packages do not import the new private
packet contract. Existing generation/drift checks remain authoritative.
