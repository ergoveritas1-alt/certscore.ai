# CookieYes loaded inventory and partial snapshot comparison

The owner authorized production deployment on October 15, 2026, after local
verification and release checks. Historical reports must not be rewritten.

## Source and capture

The canonical CMP registry selects `cookieyes_loaded_configuration.v1`.
The same bounded reader serves passive consent-proof capture and the isolated
preference observer. It reads own data properties from the already-loaded
`window.cookieyes._ckyStore._categories` and active-language store. Cookie names
must occur in category references; purpose and duration require an exact
`cookie_id` match in the active-language record. Missing translations, unavailable
description placeholders and malformed records remain missing detail.

The public CookieYes banner renderer uses these fields to build its audit table.
That table may be disabled. Configuration evidence is not proof that a visitor
was shown a declaration. The existing `cmp_api_inventory` source denotes loaded
CMP configuration; retained diagnostics and limitations identify this adapter
and explicitly state `loaded_configuration_not_visibility_proof`.

Source references:

- https://www.cookieyes.com/documentation/how-to-display-a-cookie-audit-table-on-your-website-using-cookieyes/
- https://cdn-cookieyes.com/client_data/72267d03a3814ff1204bd164/script.js
- https://cdn-cookieyes.com/client_data/72267d03a3814ff1204bd164/banner.js

The reader examines at most 32 categories and 100 cookie references, retains
bounded text only, and performs no fetch, getter call, consent-store read, click,
cookie mutation or retry. It does not derive named services or cookie purposes
from category membership or domains. It never asserts complete inventory.
Existing exact-document checks invalidate changed or ambiguous captures.

## Canonical interpretation

New materializations use `cmp_inventory_tables.v9` and
`independent_cmp_basic_facts.v5`. Typed capture, verified retained bundle,
assessment, normalized concern, policy and checklist remain the only path.

A representative runtime visit with only the documented page-inventory settling
limitation may compare a retained, time-bounded pre-consent cookie snapshot with
captured declarations. Its runtime lane must retain the exact target, successful
HTTP status and no challenge. Other limitations, unavailable lanes, foreign URLs,
missing snapshots and out-of-window capture times remain ineligible.

These comparisons are always **Partially assessed**. They do not establish
complete capture, missing declarations, service absence or a scoring deduction.
Existing usable-runtime comparison rules are unchanged. Saved assessments and
historical reports keep their original conclusions.

## Verification and cost

Fresh local sharded scans used the existing AWS Ireland proxy with browser and
HTTP egress verification. Cohere retained 89 names, 69 substantive purposes and
89 durations in both passive and preference evidence. Its four Not assessed
checks became one Not assessed and three Partially assessed checks. The combined
unresolved count is still four. No unsupported DataGrail inventory adapter was
added for Groq.

No lane, network fetch, model call, timeout, retry, coordinator tail or standing
capacity was added. Capture uses existing row/byte and worker budgets inside the
owner-approved $100/month preference envelope. This diagnostic round, including
three full local scans and bounded inspections, is estimated below $0.50.

Tests cover unavailable and mismatched language data, placeholders, unsafe getters,
resource-free text parsing, bounded lists, ambiguous CMPs, document drift,
canonical concern projection, incomplete capture and score-neutral behavior.
