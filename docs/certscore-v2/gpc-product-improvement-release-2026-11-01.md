# CertScore.ai GPC product improvement: local first release

Implementation base and current HEAD: `1f2869f49a3ea558c7510ba4321f8c6e0bfb0291`.
The initial worktree was clean. This work is local and uncommitted. No scan,
production database, production artifact download, deployment, package publication,
account creation, policy retrieval, target contact or production flag change was
performed. No database migration is needed for these optional JSON additions.

## Proof and ownership

`certscore.gpc-guidance.v1` is a bounded union discriminated by stable diagnosis
code. Adverse items require their existing canonical `gpc_response` or
`gpp_propagation_inconsistency` owner. Neutral availability has no finding owner.
`buildGpcGuidance` consumes surfaced unified findings and their typed assessments;
React, PDF, Markdown and MCP do not diagnose evidence independently.

The contradiction uses the authoritative California policy reason for verified
site-recorded GPC receipt with an applicable opt-out off. Visible acknowledgment
alone cannot supply receipt. Qualified collection uses the existing policy's
qualified IDs and vendor findings, preserving request-local restrictions,
independently eligible siblings and historical qualification versions. The two
GPP cases use the surfaced propagation owner's own bound rows. A later terminal
CMP observation cannot establish earlier state. Unresolved-purpose collection,
analytics, generic advertising and script/resource presence are not promoted.

Guidance leads with the observation, responsible role, specific investigation and
conditional correction steps, then independent fresh GPC-off/on retesting. Up to
eight applicable canonical request evidence IDs per case include sanitized canonical labels
and retained visit-relative times. Labels pass the existing public evidence-text
sanitizer and a restrictive label grammar; new guidance never includes URL paths,
queries, payloads, headers, raw identifiers, GPP strings, document tokens or storage
values. Unknown availability remains distinct internally: unavailable, unsupported,
not_ready, invalid and incomplete do not become an adverse result or honoring claim.

Customer projection, direct JSON evidence rendering and canonical JSON export share
one typed predicate that removes optional GPC producer capture/document bindings.
Original canonical assessments and receipt hashes remain intact for policy and
verification. The output walk preserves dates and does not inspect unavailable
source bytes. A regression exercises unsanitized direct renderer inputs as well as
the normal canonical projection; producer document tokens never reach either.

## Separate paired-state packet

`certscore.gpc-cmp-state-comparison.v1` is an optional canonical sibling of activity
comparison, exposed as `gpcResponse.cmpStateComparison`. It contains only scan ID,
the two original source hashes, supported section/version, each side's sale/sharing
state, GPC receipt and semantic time after its own document commit, plus the fixed
neutral effect/causation/legal literals. Strict schemas enumerate US National 7 v1/v2
and California 8 v1, independently known sale/sharing axes, bounded integer times,
independent hashes and no extra properties. OpenAPI and standalone SDK types are
generated with the same section/version alternatives. Public packages import no
private runtime contracts; public Zod types remain named.

The coordinator derives it from the same already-loaded original worker bytes and
pointers used at the existing merge barrier. Length, SHA-256 and canonical schema
verification precede the strict internal impact assessment. The internal contract's
`internal_only` and `productionProjectable` literals remain unchanged. Both measured
impact and comparable CMP state are required, followed by additional independent
gates: exact parent and isolated lane, matching target/destination/context/region,
representative usable successful visits, original coordinator dispatch-target binding, actual off/on delivery, ready/loaded
terminal supported GPP state with matching section **and version**, known applicable
sale and sharing notice/opt-out values, state hashes and original timing/loader joins.
Local/adaptive diagnostic retention and diagnostic-only longer horizons are excluded.

Baseline semantic capture binds to its own original impact document/loader token
and stable readback. It does not borrow the GPC producer capture ID. GPC must also
pass its existing source/session/document/semantic completion checks, including the
hashed inline producer session and agreement with its original impact document.
The two visits deliberately have different tokens and sessions. No browser work,
object fetch, wait, invocation, retry, polling, late publication or new lane is added.
The coordinator fixture asserts the same four source reads/four passive workers and
one canonical result upload.

At runtime materialization, normalized concern, unified finding, canonical report,
public response and PDF boundaries, the reader verifies schema, scan ID, both hashes
against the authoritative assessment pair and agreement with the authoritative GPC
current state. The GPC semantic time must fit its retained observation window. No
reader claims to rehash unavailable bytes. Source/state mismatches omit the optional
packet while preserving the original findings. API schema validation rejects a
conflicting public packet. Text surfaces also check the enclosing scan identity.

## Wording, surfaces and compatibility

The shared neutral table is titled **Site-recorded opt-out settings**, with
**Without GPC** / **With GPC** and **Sale opt-out** / **Sharing opt-out**, using On/Off.
Timing and the approved non-causation context are under an evidence expander. These
are independent fresh-visit current-state snapshots, separate from the matched
request-count horizon. They do not establish a GPC-caused transition, returning-
visitor behavior, persistence, account fulfillment, downstream treatment or a legal
outcome. No new banner, positive compliance badge, checklist credit or priority is
introduced. Full-session facts and the matched request table remain ahead of the
new contextual material.

Both active web report routes reuse the new presentation component. Legacy GPC
point amounts/explanations in the separate `/app/scanso2` renderer were removed;
typed score data and policy effects are preserved. API/canonical JSON, PDF, Markdown
and MCP use the shared projection and formatting. PDF priority selection remains
unchanged. The PDF v2 model supports only EU starting-page presentation, so no GPC
panel was added there. EU-focused customer web/PDF scope is unchanged; jurisdiction-
neutral machine-readable evidence remains available as before.

Missing legacy packets stay absent. No baseline is inferred from the merged GPC
observation, no “unchanged” fallback is manufactured, and no historical artifact is
read at report time to create this packet. Descriptive guidance explains existing
canonical findings without changing their interpretation. The materialization cache
moves from v42 to v43. The global report projection stays v27: its current-version
readiness checks participate in repair decisions, so changing it would risk historical
reprocessing. Existing readable versions and optional old records remain compatible.
No repair, backfill, historical rewrite or lazy reconstruction was introduced.

## Local review and measurements

Review artifacts are in `outputs/gpc-product-release/` and are separate synthetic
review outputs, not historical report evidence. `verify-gpc-product-release.tsx`
serves only a fixture at `http://localhost:3000/gpc-product-fixture`; the listener was
inspected first and no existing preview was running. Playwright rejects unexpected
requests, blocks service workers, checks Enter/Space expanders, verifies no page
horizontal overflow at 390/1280 pixels and records zero external requests. Native
expanders need no client-side diagnosis. California and EU PDFs were generated;
the new California guidance page was rendered and visually checked. PDF text and
EU omission are also covered by deterministic tests. No application build was needed.

Measured synthetic packet: **633 bytes**. Typical coexisting-case guidance:
**3,261 bytes**; all five cases with eight references per applicable case:
**7,105 bytes**. These exclude existing response facts. On the local small pair,
producer median/p95 were about **0.39/0.89 ms**; five-case diagnosis about
**0.62/1.02 ms** (100 measured iterations after 20 warmups). Exact run values are in
`metrics.json`; timing varies with local load and does not measure Lambda savings.

The shared public redaction walk, measured separately on a 173,655-byte synthetic
whole-export candidate with original typed assessments, removed 638 bytes and took
**0.42 ms median / 0.51 ms p95** over 100 iterations after 20 warmups. This is within
the combined processing allowance below, reduces output size and adds no requests.
The measurement is in `remaining/public-redaction-metrics.json`.

One original local convenience pair was replayed read-only using its adjacent
original receipts (436,818 and 453,879 bytes); hashes were verified, never replaced.
It remains insufficient/comparison-unavailable and produces no public packet. The
added producer evaluation measured **11.52 ms median / 12.17 ms p95** over 20 local
iterations. `retained-evaluation.json` contains only internal eligibility/measurement
metadata. This sample and synthetic fixtures do not establish production population
coverage. Missing or unverifiable original prerequisites continue to omit the packet;
no capture expansion is proposed to improve these results.

Combined conservative recurring planning estimate: **at most $0.90/month** at
100,000 scans and 30-day retention. This allows about $0.30 for 50 ms of added work
per scan at 3 GB-equivalent compute, $0.24 for up to 2 GB of incremental retained/
cached output, $0.20 for up to 2 GB of additional transfer and $0.16 contingency,
using conservative planning rates of $0.00002/GB-second, $0.12/GB-month and
$0.10/GB transfer. It includes packet copies and bounded guidance, with no new
requests or provisioned capacity. Actual local work adds $0 recurring AWS cost.
This is one combined estimate, not separate allowances or measured billing savings.
The preliminary below-$0.90 estimate was disclosed before implementation; the final
estimate remains below the owner approval threshold. No configured infrastructure,
paid-service, model or capture-budget increase is included.
