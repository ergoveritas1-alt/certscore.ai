## Admission and execution gates

1. **Quality review:** Luna reviews the completed URL/evidence packet and exact manifest/list diff, confirms role/lane coverage and leaves existing baseline labels and thresholds intact. This proposal is not that approval.
2. **Operational review:** SO reviews normalized-domain uniqueness, aliases, current repository contact holds and a successful central all-channel export scoped to the proposed expanded manifest. Retain existing manual restrictions and later timestamps. No cooldown overrides, region/identity switching, or blank ledger clearance.
3. **Admission:** after those decisions, commit only the approved inventory change and any honestly sourced manual-ledger adjustments through the normal repository process. Manifest and canonical URL list must match exactly in order. The validator allows 30–100 targets, so a conditional 61-target inventory needs no size-limit change. A filename containing `50` is not permission to rename canonical paths.
4. **Pre-run selection:** run the registry check and obtain a fresh expanded-manifest central export immediately before canonical selection. Fix the rotation key before outcomes. Require exactly ten selected distinct domains and review the selected packet for holds, role/lane sufficiency, region allocation and SO attestation. No partial run when only nine are eligible.
5. **Authorized run only:** use the existing authorized deployed scan creation/control-plane path and graph rollout controls, pinned to tested revisions, with persisted graph dispatch selection. The generic local Scan Lab workflow is not the deployed sharded graph runtime and does not establish this gate. The pool change confers no consent-action authority and no graph activation authority. Any action must independently satisfy the existing exact-URL, one-action, confirmed-transition restrictions. Preserve one scan per domain, no automatic no-go retry and no alternate-region bypass. Propose a reviewed 4/3/3 allocation across the three approved regions if supported by the authorized execution path; never rescan a domain in another region to fill a stratum. Ten total public creations remains the ceiling.
6. **Record and review:** verify the cohort, retain incomplete/no-go denominators and coverage gaps, persist contacts with the idempotent run key, generate the manual-ledger candidate, and have SO review/commit it before another public run. Luna decides baseline/regression acceptance from retained evidence. A contacted failed/no-go target consumes its contact and release allowance; reserve nominations do not permit an eleventh public scan.

Implementation limits found in the current tools matter to this process. The selector treats a missing ledger entry as eligible and does not itself check `PUBLIC_TEST_CONTACT_HOLDS`. The exporter queries only domains present in its input manifest. The validator checks URL uniqueness, not normalized-domain uniqueness. Consequently an old 51-domain export, a blank ledger, or a successful selector exit cannot certify new domains. The proposed workflow uses explicit review of these boundaries; this proposal does not modify runtime or selection policy to hide them.
