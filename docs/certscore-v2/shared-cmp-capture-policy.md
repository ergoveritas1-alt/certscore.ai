# Shared CMP capture and source coverage

Local implementation, October 15, 2026. No production deployment is authorized.

## Early retained checkpoints

The existing rapid typed first-layer observation may start the single passive
CMP basic read before DOMContentLoaded, when it contains positive visible
controls and matches the live document URL and loader. It does not reuse early
absence, authorize actions or replace representative geometry/screenshot proof.
The existing 350 ms read slice and lane deadline remain unchanged.

`cmp_capture_checkpoints.v1` retains controls, configured declarations and
privacy-link access independently. Each checkpoint rechecks the exact target
and loader, validates a detached typed packet and records its capture time.
Completed positive facts survive a later optional-stage timeout. Missing stages
stay unknown. Navigation drift invalidates projection. Publication closes the
capture, so a pending operation cannot mutate the published packet or telemetry.

Basic and preference captures inspect core controls before configured details
and whole-document link work. Preference evidence remains versioned as
`cmp_preferences.v12`. The pre-action privacy hit test still precedes Options:
moving it after opening the panel would change the observation's meaning.
An empty first-layer toggle read does not become an absence checkpoint.

## Source-specific cookie coverage

`bound_cookie_snapshot.v1` describes one successful, unchanged-document,
pre-consent browser-context cookie snapshot. It records the exact target,
document loader and ordered capture times, without cookie values. Context
failure, abort or document drift cannot emit completed coverage. Only the
baseline runtime lane emits it; GPC pairing and action evidence are unchanged.

The coordinator retains it with runtime-owned cookie evidence. WC01 verifies
its representative runtime visit, exact target, capture bounds and matching
runtime metadata document before assessing a point-in-time CMP name comparison.
Unfinished unrelated DOM loading does not erase that independently completed
snapshot. A canonical continued diagnostic visit with successful exact-target loading and
no blocking-frame challenge may retain this factual comparison. It cannot
receive a broader missing-declaration Review from that diagnostic context.
A canonical No-Go visit remains ineligible. The comparison does not establish a
settled page, quiet network,
future inactivity, consent registration or legal compliance. The broader
missing-declaration Review gate retains its existing runtime-coverage rule.

## Compact inventory accounting

`cmp_inventory_manifest.v1` separates cookie names from the existing detailed
description sample. It retains at most 256 unique names and 8,192 name
characters, plus source counts, unresolved sources and truncation. Detailed
records keep their existing limits. Adapters read only registered public
configuration fields or already-loaded declaration cards; no cookie values,
new fetch, SDK mutation or extra preference action is introduced.

* CookieYes enumerates the own-data category cookie configuration. Only a fully
  resolved, untruncated enumeration with no conflicting detailed declarations
  supports complete configured-name comparison. This covers that captured
  configuration, not the entire website or later dynamic configuration.
* OneTrust retains names from its registered group cookie lists independently
  of vendor/description limits. Those lists do not establish exhaustive CMP
  coverage, even when the retained manifest is untruncated.
* Cookiebot retains name breadth beyond the detailed card allowance. Its
  collapsed DOM cards remain a partial source and cannot establish configured
  completeness. Explicit non-cookie storage types are excluded from cookie
  comparisons.

Provider, loader, checkpoint, revision and source-accounting guards remain in
the typed contract. Contradictory, malformed, missing or truncated sources fail
closed. CMP assessment policy `cmp_inventory_tables.v13` and passive basic
policy `independent_cmp_basic_facts.v6` feed normalized concerns, concern policy,
unified findings/checklist and the shared report projection. They do not change
scoring weights or rewrite historical assessments.

## Verification and cost

### Local terminal comparison repair, October 16

`terminal_pair_first.v3` permits the existing synchronized CMP-control image
to consume the single 80 ms comparison allowance when the producer explicitly
marks the pair terminal and its frame set remained stable. Complete structured
inspection, exact loader/URL binding, capture skew, unique visible controls and
visual safety review remain required. It does not add an image decode, retry,
capture, safety review or timeout allowance.

The producer tracks the latest retained geometry independently of accumulated
observation notes. A historical negative surface note cannot trigger replacement
of newer complete, positive geometry from the same URL and loader. Missing,
limited, negative or document-mismatched geometry still permits the existing
revalidation path. Historical notes remain retained. This affects scheduling,
not assessment or display eligibility.

`label_bound_necessary_only_reject.v2` adds the exact label "Accept only
necessary" to the named OneTrust Reject proof. The canonical registry and
retained-proof validator share one versioned label vocabulary. The exact
registered banner and control, unique enabled native button, non-form context,
target binding, hit test and final dispatch recheck remain required. The generic
action classifier continues to reject this observation-only phrase. Registration
still requires the existing verified refusal transition; the label alone cannot
create an After Reject result. Version 1 proofs retain their original vocabulary.

These repairs are local only. The incremental bounded comparison work is
estimated below $1/month at 100,000 scans. The action repair uses the existing
owner-approved action lane and observation budget. No new lane, per-scan browser
session, model call, deadline or standing capacity is introduced.

Use deterministic streaming/timeout/drift fixtures, historical replay and
ledger-selected fresh Ireland diagnostics. Report newly incomplete checks as
well as resolved checks; do not treat a bounded partial source as a failure to
be removed by inference. The targeted cohort is not a release acceptance gate.

No new lane, per-scan browser run, model call, retry or timeout increase is
introduced. Bounded metadata and processing are estimated below $1/month at
100,000 scans with 30-day retention. One-time verification uses the existing
Ireland proxy and is estimated below $1 total.

### Local reliability follow-up, October 16

Safety pair eligibility reuses an immutable digest and PNG dimensions from the
existing capture-time review job when available. This removes a duplicate local
image read; it does not grant eligibility from an image label or skip structural
proof. After a safe review, the gate still rereads the retained file and requires
literal equality to reviewed bytes and the paired hash. Replaced, removed,
withheld, malformed and sensitive images remain unavailable. The 75 ms local
eligibility window, four-second verified-pair absolute deadline, request count,
concurrency and fail-closed deletion are unchanged. Bounded eligibility status
and elapsed time are retained in the existing review diagnostics.

Preference binding resolves independent root, tab and dialog handles concurrently
inside the existing 17-second inspection budget. Exact uniqueness, ancestry,
pre-action privacy access, final dispatch identity, one-click authorization and
post-opening panel verification remain required.

`named_reject_routing.v1` is a passive scheduling witness produced in the existing
geometry DOM read. It requires the canonical named recipe, unique native enabled
non-form control and its unique registered banner. The worker may retain the
existing Reject tail only for a matching visible control, current recipe, exact
target, `cdp_loader_id`, stable main-frame capture and observation within 500 ms.
This repairs the mismatch between the approved named necessary-only action recipe
and generic observation-only routing. It does not authorize a click or establish
registration: the independent action observer must verify its full live action
proof. Missing, mismatched or historical proof retains previous passive-only
routing. The eight-second tail cap and single terminal publication are unchanged.

A fresh Ireland Cookiebot diagnostic completed its preference inspection in
14.831 seconds and verified paired-image eligibility in 1 ms. Its canonical CMP
projection reduced unresolved checks from the latest six to one: four recovered
regressions and one new prominence assessment relative to the earlier two-check
baseline. The remaining inventory comparison is explicitly partial. This single
run does not prove that the earlier 75 ms race caused every image failure or that
panel reliability is now stable.

The corresponding OneTrust run failed at the public-network target guard before

These changes remain local, with no deployment or historical report rewrites.
Bounded metadata and local processing are estimated below $1/month at 100,000
